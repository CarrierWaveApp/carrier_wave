# Carrier Wave — Design Context

## Users

Amateur radio operators (hams) — from casual POTA activators to serious contesters and DXers. They use Carrier Wave in the field (parks, summits, portable setups) and at home stations. Context is often time-pressured: logging QSOs mid-pileup, scanning spots during a contest, reviewing activity after a session. They are technically literate, accustomed to dense information displays (rig faces, logging software, band maps), and frustrated by apps that hide data behind extra taps.

## Brand Personality

**Technical. Dense. Power-user.**

Like a well-organized shack — every control accessible, information-rich, rewards expertise. The interface should feel like it was built by an operator who logs 500 QSOs on a contest weekend, not by a designer who thinks radio is charming. Respect the user's competence. Show more, not less.

## Emotional Goals

**Flow and momentum** above all. The app should disappear during operation — logging is fast, navigation is instant, the next action is always obvious. When a ham is in the zone during an activation, nothing should break rhythm. Confidence (trust the data) and pride (this is a beautiful tool) support flow but never compete with it.

## Aesthetic Direction

Inspired by **Linear, Raycast, Arc** — modern developer tools that are dense but refined, dark-themed, keyboard-aware, and respect power users. Not flashy, not minimal — *precise*. Every pixel earns its place.

- **Theme**: Dark by default across all surfaces. The app adapts via system semantic colors (light/dark), but the brand identity is dark.
- **Density**: High information density. Compact rows, monospaced data columns, tight spacing. Whitespace is intentional separation, not filler.
- **Typography**: Monospaced for all radio data (callsigns, frequencies, RST, grids, times). Proportional sans for UI chrome and prose. Sharp weight hierarchy — bold values, medium labels, regular body.
- **Color**: Purple/magenta brand palette (`#9B4DCA` / `#C94BC4`). Blue for informational/default accent. Semantic colors for states (green/success, red/destructive, orange/warning, purple/commands). Muted surfaces, vivid accents.
- **Motion**: Minimal and fast. Spring animations for panel transitions, ease-out for dismissals. Nothing bouncy, nothing slow. Motion serves state changes, never decoration.

## Anti-References

- **Generic ham apps** with skeuomorphic dials, wood textures, or amateur UI (N1MM+, HRD — functional but visually dated)
- **Over-designed consumer apps** that prioritize aesthetics over information density (most weather apps, social media)
- **AI slop** — gradient text, glassmorphism, identical card grids, purple-cyan neon palettes
- **Minimalist apps** that hide functionality behind menus and progressive disclosure at the cost of speed

## Design Principles

1. **Density over decoration** — Show the data. Compact layouts, tight spacing, no ornamental whitespace. A screen that shows 20 QSOs is better than one that shows 8 with pretty cards.
2. **Speed is a feature** — Every interaction should feel instant. Optimistic UI, no loading spinners where avoidable, keyboard/command-driven workflows.
3. **Radio data is sacred** — Callsigns, frequencies, RST, grids, and times are always monospaced, always precise, always prominent. Never subordinate radio data to UI chrome.
4. **Earned complexity** — The interface is dense but never chaotic. Information hierarchy is maintained through weight, color, and spacing — not by hiding things.
5. **One brand, many surfaces** — iOS app, macOS companion, website, and documentation should feel like the same product. Purple/magenta identity, dark palette, technical typography, consistent component patterns.

## Scope

Whole brand — iOS app (Carrier Wave: Field), macOS app (Carrier Wave: Sweep), marketing website, documentation site. Design decisions should unify all surfaces under one coherent identity.
